Try these

  1. Capture Area from the tray menu, or Win+Shift+S in the real app. Drag a box. Watch the magnifier, the hex color, and the size.
  2. Press Space during a capture for window mode. The window comes out alone.
  3. Hover the corner card: Copy, Save, and the corners Pin, Close, Markup, Show in Explorer. While hovering, Ctrl+C / S / W / E / P work too.
  4. Drag the card into the Chat window.
  5. Open Markup. Every tool and its key, colors, sizes, undo, Background, the small picture to drag out, and Done.
  6. All-in-One for the bar, then Record Screen…, then stop from the red item in the tray.
  7. Open History (Win+V in the real app). Type to filter, arrows, Enter pastes.

Talk to type

Click into this page, then hold Right Alt (Right Option on a Mac) or hold the button. Let go to type into Notepad. Tap twice to lock, press again to stop. Esc cancels.

Only on Windows

  • Navi lives in the tray. Windows 11 hides new tray icons, so the first run shows how to keep it visible.
  • No Screen Recording or Accessibility permission. Only the microphone asks.
  • Hide desktop icons really hides them for a moment while a shot is taken (Windows can't leave them out of the capture).

The idea

One product, two native apps. The Windows build is a separate app in this repo under windows/, written in C# on .NET 10 with WPF. It copies the Mac app feature for feature and pixel for pixel: the same menu, settings, cards, editor, pill, record bar, and history, with the same sizes, colors, radii, timings, and words. Both apps read and write the same files (history.json, .navi), so they behave the same and their tests can share fixtures.

Stack

App

  • C# 14, .NET 10 LTS, WPF
  • Win32 through CsWin32 (generated, no hand-written interop)
  • Acrylic backdrop for Navi's panels (DWMWA_SYSTEMBACKDROP_TYPE)
  • Per-Monitor V2 DPI awareness
  • Windows 11 22H2 and later, x64 and ARM64

Engines

  • Capture: Windows.Graphics.Capture through Vortice.Windows
  • Video: Media Foundation H.264/AAC, hardware encoder
  • Audio: NAudio (WASAPI mic and loopback)
  • Speech: Parakeet TDT v3 through sherpa-onnx
  • OCR: Windows.Media.Ocr. QR: ZXing.Net
  • Stitch: OpenCvSharp. GIF: gifski DLL

Ship

  • Velopack: installer, delta updates, the same daily check as Sparkle
  • Azure Trusted Signing (Authenticode) so SmartScreen and antivirus trust the keyboard hook
  • GitHub Releases next to the Mac zip

How it gets tested

On this Mac

All *.Logic and Navi.Core projects target plain net10.0, so dotnet test runs here in seconds. This is where most of the code lives.

In a Windows VM

Parallels with Windows 11 ARM. The agent connects over SSH and runs the Windows tests, FlaUI flows that drive the real app, and snapshot tests that draw each window to PNG (like EditorSnapshot) to compare with the Mac build.

In CI

GitHub Actions windows-latest runs everything on each push, plus a parity check: the same fixture history and .navi files open the same in both apps.

Steps

Same order as the Mac build. Weeks are for one developer working full time; an agent with the VM loop may go faster, but these are the numbers to plan against.

Risks

  • Antivirus and the keyboard hook. Low-level hooks look like keyloggers to some antivirus apps. Signing from day one and a clear first-run screen lower the risk.
  • Mixed DPI displays. The overlay and magnifier must line up to the pixel on a 150% laptop next to a 100% monitor. Test from step W2, not at the end.
  • Right Alt on European layouts is AltGr. Navi checks the keyboard layout and picks Right Ctrl there.
  • Taking over Win+Shift+S and Win+V means Navi has to pass them back cleanly when it quits or crashes. A watchdog restores them, like SystemScreenshotShortcuts does on SIGTERM.
